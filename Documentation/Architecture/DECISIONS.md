# Decisions

## Early decisions (D-1 to D-11)

Taken before the first version of the checklist viewer was built, where the architecture document and the plan left something open or disagreed. One line each; the later decisions below continue the numbering from D-12.

- D-1: **`ARCHITECTURE.md` overrides the plan on every conflict** (Bloc/Cubit, not `provider`; layered folders, not a flat layout; `ChecklistDocument`, not `ParseResult`; fixtures in `testing/fixtures/`; state keyed by name, not index). The plan only fills gaps: parser rules, UI details, acceptance criteria.
- D-2: Check state is keyed by **checklist name**. The parser therefore makes names unique: a duplicate becomes `Name (2)` with a warning. Two checklists with the same name would otherwise share check marks.
- D-3: `package:equatable` is allowed in `domain/`. The architecture says "Dart core only" but also lists equatable for models; it is pure Dart, so the layer script allows it.
- D-4: **No in-app "Load sample" button.** There is one `ChecklistSourceService` seam. The bundled sample was a second implementation of that seam, chosen in the development wiring, and `ChecklistRepository` stayed as the architecture sketches it. (Both the file source and the sample are gone; see D-69.)
- D-5: The **parse-warnings banner lives on the checklist list screen**, because a successful load navigates straight to the list.
- D-6: A document with **zero checklists** is an error from the repository (`ParseFailure`), not an empty success, so the home screen can show a clear message.
- D-7: `ChecklistProgressRepository` has `resetAll()`, and `HomeCubit` calls it after every successful load, so check marks from the previous file do not leak into the next.
- D-8: Latin-1 fallback decoding lives in `lib/utils/text_decoding.dart` (pure Dart), shared by every source of checklist text.
- D-9: Tests of temporary code lived under `test/**/temporary/`, so deleting the temporary code deleted its tests too. (Done; the isolation gate now fails if a `temporary/` folder returns.)
- D-10: `ChecklistDocument` carries `sourceName` (the name to display for where the checklist came from).
- D-11: Parse edge policies the plan left open: an empty checklist name becomes `Untitled checklist N` plus a warning; an empty `sw_itemvoid` is skipped with a warning; the result is the text after the first `|` up to the next `:` (so `A|B|C` gives the result `B|C`).

## Optional check-state persistence

Date: 2026-10-22. Decision: **no, defer** (the optional persistence is not built in the first version).

Reason: the first version is complete and meets all six acceptance criteria without it. Check marks reset when the app restarts, which is acceptable for a hand-ticked checklist. The seam is already in place (`ChecklistProgressRepository` with a future `services/local/` implementation), so adding it later changes no UI or domain code. `shared_preferences` is planned anyway, and persistence is better designed together with auto-check, which writes to the same repository.

## Check-state persistence revisited

Date: 2026-10-23. Decision: **yes, build it**; supersedes the deferral above.

Reason: if the app is killed mid-flight the pilot must not lose their place. Restore rule and storage are in `ARCHITECTURE.md` section 16.
